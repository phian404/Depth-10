## Источники и решения по противоречиям

- Источники: `docs/scenes/SC001_signing.md` (главный), `docs/art/art_direction.md`, `docs/canon/00_master.md`.
- **Перчатка.** В `00_master.md` у Дяди «руки в перчатке», а в `SC001_signing.md` и в задаче «Перчатки в сцене нет». Побеждает документ сцены, перчатки нет.
- **Файлы.** AGENTS.md ограничивает ответ одним файлом. Выдаём `scenes/SC001_Blockout.tscn` (только через `redot_scene_action`) и один скрипт `scripts/sc001_signing.gd` (до 150 строк).
- **project.godot не трогаем.** Главную сцену не назначаем, запуск через F6 или `run` с путём сцены.
- **640×360.** Задаём в `_ready()` скрипта: `get_window().content_scale_size = Vector2i(640, 360)`, mode `VIEWPORT`, aspect `KEEP`. Апскейл nearest, project.godot не меняется.
- Звук, документ-оверлей, подпись, биты 01–09 и пост-стек (квантование, дизеринг, зерно) не входят в этот блокаут. Это только пространство, свет, силуэты, постукивание и обзор.

## Система координат

1 ед. = 1 м. Y вверх. Игрок смотрит в −Z. Лево игрока = −X.
Комната X∈[−2, 2], Z∈[−2, 2], высота 2.7. Стол по центру, длинная сторона вдоль X: 1.5 по X, 1.0 по Z. Дядя сидит на коротком расстоянии (1 м через стол).

## Скрипт `res://scripts/sc001_signing.gd` (≤150 строк)

Типизированный GDScript, табы, комментарии по-русски.
1. `_ready()`: content scale 640×360 (см. выше), `Input.mouse_mode = CAPTURED`, fade-in tween 2 с, старт цикла постукивания.
2. Обзор: движение мыши накапливает целевые yaw/pitch, clamp ±35° / ±15° (поверх базового pitch −12° считать оффсет), сглаживание `lerp` с коэффициентом 8.0. Esc (`ui_cancel`) освобождает мышь.
3. Постукивание: цикл по таймеру, одиночные удары с паузой 0.9–1.4 с. Tween поворачивает шарнир Finger на ~−18° и обратно за ~0.09 с. Простой >16 с: амплитуда и частота растут (диегетическая подсказка, без других действий). Тройной/тройной паттерн бита TAPS не делаем.
4. Лампа: мерцание ±0.5% медленным шумом, редкое выпадение 0.05–0.15 с раз в 8–30 с.
5. Использовать `@export var`/`@onready` для узлов: `Camera3D`, `Finger`, `SpotLight3D`, `ColorRect`. Не выдумывать API; незнакомые вызовы сверять через `redot_code_intel(get_docs)`.

## Порядок реализации

1. `redot_scene_action create` сцены `res://scenes/SC001_Blockout.tscn`, корень Node3D `SC001`.
2. Добавить узлы по дереву выше через `add`, свойства через `set_prop`. Материалы встраивать (sub-resources) через `redot_resource_action`/`set_prop`, при невозможности создать `.tres` в `res://materials/` (мало файлов, использовать именование `M_...`).
3. Написать скрипт, `redot_code_intel validate`, прикрепить к корню `SC001`.
4. Запуск `redot_project_config run` со сценой, ждать 3–5 с, `redot_game_control capture`. Итеративно подстроить энергию/угол лампы, камеру, положение Дяди и охранника, пока: пятно света на папке и руке, лицо Дяди и охранника не читаются, охранник виден только силуэтом.
5. `redot_project_config output` на ошибки, затем `stop`.
6. Коммит одной строкой, когда сцена запускается.

## Риски

- Силуэт охранника: при слишком тёмной сцене пропадёт, при слишком светлой нарушит канон. Регулировать освещением стены за ним, не добавляя источников.
- Редактор сам ставит 3D-обзор в окне, content scale действует только при запуске игры.
- `scenes/` может содержать `.keep` из прошлого плана; не удалять без явной просьбы.
- Если `redot_scene_action` не умеет задавать вложенные материалы, создавать `.tres` через `redot_resource_action`. Это увеличит число файлов, нужен явный ответ пользователя перед этим.
