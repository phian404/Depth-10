# План: доводка SC-001 «Подписание» до спецификации

## Цель
Реализовать все биты и взаимодействия из `docs/scenes/SC001_signing.md`, которых ещё нет в блокауте: открытие папки и чтение контракта, взятие ручки, подпись с порогом покрытия 72%, бит постукивания (3+3), выключение света и переход. Сцена должна проходиться без HUD-текста и без субтитров.

## Контекст
- Сцена: `scenes/SC001_Blockout.tscn`, скрипт `scripts/sc001_signing.gd`.
- Уже есть: обзор мышью в конусе, мерцание лампы, процедурный гул, ритмичное постукивание пальцем, fade-in.
- Не хватает: интерактивы папка/ручка/подпись, оверлей документа, бит TAPS, бит LIGHTS_OUT, звуки папки/ручки/пера/выключателя/стула/двери/мотора.
- Пост-стек (Q18) и оверлей CCTV не входят в эту задачу; они отдельными спайками.

## Задачи

1. **Ввод и состояния**
   - Добавить флаги сцены: `read_contract`, `treatment_leverage_seen`, `pen_taken`, `signed_contract`, `met_somov_voice`.
   - Ввести состояния взаимодействия: `idle` → `folder_open` → `pen_taken` → `signing` → `signed`.
   - Клик/пробел по папке открывает/закрывает документ; клик вне листа или Esc закрывает.
   - Взятие ручки доступно только после `read_contract`.

2. **Оверлей документа**
   - Добавить `CanvasLayer` с `ColorRect`/`Label` (или TextureRect с заранее подготовленной текстурой документа) поверх 60% высоты кадра.
   - Текст контракта по спецификации (ПОДРЯДЧИК, ОБЪЕКТ, СРОК, АВАНС, ОСОБОЕ УСЛОВИЕ, штамп СОГЛАСОВАНО).
   - При открытии мира приглушается звук на −6 dB; при закрытии возвращается.
   - Бездействие >16 с делает постукивание отчётливее (уже есть), без текста.

3. **Подпись (Q20)**
   - Линия подписи — интерактивная зона на оверлее; при удержании и движении мыши рисуется штрих (Line2D или набор точек).
   - Подсчёт покрытия: разбить строку на бины (N сегментов), отметить бин при прохождении штриха; принять при ≥72%.
   - При отпускании проверять покрытие; при успехе — флаг `signed_contract`, дата 12.11.2006 проступает.
   - Звук пера: прерывистый скрип 2.2–4 кГц, привязанный к движению.

4. **Бит TAPS**
   - После подписи: три удара пальцем, пауза, ещё три удара, затем прекращение постукивания.
   - Использовать существующий `tap_player` и анимацию `finger`.

5. **Бит LIGHTS_OUT**
   - Щелчок выключателя (4.2 кГц HP + 220 Гц), свет гаснет за 0.1 с, гул лампы затухает.
   - Скрип отодвигаемого стула, дверь, удаление мотора микроавтобуса.
   - Полная темнота 2 с, затем переход (пока — чёрный экран; следующая сцена вне задачи).

6. **Звуковые файлы**
   - Папка: шелест 0.34 с + удар 90 Гц.
   - Ручка: щелчок 3.4 кГц + 320 Гц.
   - Выключатель/стул/дверь: по спецификации (можно процедурно или файлами; файлы предпочтительнее для foley).

7. **Валидация**
   - `redot_code_intel(action="validate")` для скрипта.
   - Запуск сцены через `--write-movie`, проверка кадров: конус обзора, отсутствие лиц, читаемость документа при 640×360, подпись принимается при ≥72%.
   - Проверка с закрытыми глазами: гул, постукивание, перо, выключатель читаются по звуку.

## Затронутые файлы
- `scripts/sc001_signing.gd` — расширение.
- `scenes/SC001_Blockout.tscn` — добавление узлов оверлея/интерактива через `redot_scene_action`.
- Возможно новые `.wav` в `audio/` (foley) — только если без файлов не обойтись; процедурно допустимо для пера.

## Риски
- Детект покрытия штриха (Q20) может быть неточным при низком разрешении; бины должны быть достаточно крупными.
- Оверлей документа не должен ломать конус обзора и рендер 640×360.
- Звуки foley требуют файлов; если их нет, использовать процедурные синтезы с пометкой TODO-долг (но не TODO в коде — отдельной задачей).

## Открытые вопросы (не блокеры этой задачи)
- Q20 (Line2D-подпись) — решается в рамках задачи, результат фиксируется в коде.
- Q22/Q24 (озвучка, формат субтитров) — для SC-001 не нужны: сцена открывается без субтитров.

## Приёмка
- Все пункты «Приёмка» из `docs/scenes/SC001_signing.md` выполняются.
- Сцена проходится без HUD-текста и без субтитров.
- `validate` без ошибок.
