## MCP Redot: проверенные ограничения

Проверено на сборке SC-001. Не трать время на повторные попытки.

- `redot_scene_action set_prop`: `mesh` и `material_override` принимают только путь `res://...tres`. Встроенные (sub-resource) меши и материалы задать нельзя. `transform` не принимается — задавай `position`, `scale`, `rotation_degrees` отдельными вызовами.
- `redot_resource_action create`: падает с ошибкой 19, если каталога нет — сначала создай папку. Создаёт только ресурс с дефолтами.
- `redot_resource_action modify`: проходят цвета и строки; числовые и булевы свойства (`radial_segments`, `height`, `emission_enabled`) не ставятся ни числом, ни строкой. Числовые параметры ресурсов пиши текстом в `.tres`.
- `redot_project_config run`: требует `run/main_scene` в `project.godot`, путь сцены параметром не принимает. Если главной сцены нет, запускай движок напрямую: `redot.windows.editor.x86_64.llvm.console.exe --path . --quit-after 120 res://scenes/X.tscn`.
- `redot_game_control capture`: работает только при подключённом мосте, часто недоступен. Для визуальной проверки: `--resolution 1280x720 --write-movie "$env:TEMP\kilo\shots\f.png" --fixed-fps 30 --quit-after N`, затем читать PNG-кадры. Записанный `f.wav` — 32-битный целочисленный PCM, не float.
- `redot_code_intel validate` работает, им проверяй каждый `.gd` перед выдачей.
- `python` в PATH — заглушка WindowsApps (код 9009). Запускай через `py`.

## Звук без файлов

`AudioStreamGenerator`: playback брать после `play()`, `buffer_length` не меньше 0.4 с, доливать до 16384 кадров за кадр, усиление сглаживать (иначе треск и щелчки на резких изменениях).

## Сцены: PackedScene.pack()

Проверено на 26.3: `PackedScene.pack(root)` сохраняет только узлы с `owner == root`. Узлы, добавленные через `add_child()`, имеют `owner = null` и в `.tscn` не попадают; ошибки нет, файл просто выходит пустым.

- После сборки дерева выставляй `owner` всем потомкам, включая вложенные.
- Проверяй результат: `packed.get_state().get_node_count()` должен равняться числу узлов, а не 1.
- `pack()` не заменяет `redot_scene_action`: правило «.tscn — только через MCP» остаётся.
- Статические меши и материалы держи в `.tres` (`M_*`, `SM_*`), а не создавай в `_ready()`: иначе сцену не осмотреть в редакторе и не подогнать по кадру. Создание в `_ready()` — только для действительно процедурного (генератор звука, анимация).

## redot_code_intel get_docs — только при неопределённости

**Не вызывать get_docs для базовых нод:** `Node3D`, `Timer`, `Spatial`, `RigidBody`, `Area`, `Camera`, `Sprite2D`/`Sprite3D`, `AudioStreamPlayer`, `AnimationPlayer`, `Label`, `Button`, `CollisionShape` — их API стабилен и не требует проверки.

**Вызывать get_docs только если:**
- Работаешь с нестандартным API (кастомные шейдеры, `RenderingServer`, `WorldEnvironment`, `PinJoint3D`)
- Сомневаешься в сигнале или параметре (например, `signal name(arg: Type)` vs `signal name`)
- Используешь ресурсы, которых нет в кодобазе (проверь `Glob`/`Grep` сначала)
- Коллега explicitly сказал «проверь через get_docs»
